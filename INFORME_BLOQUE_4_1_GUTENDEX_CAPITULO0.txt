9. ERRORES, PAGINACIÓN Y RESPUESTAS ANTIGUAS
HTTP público con Accept application/json, timeout de 15 segundos y sin Bearer.
No sigue redirecciones de la API. HTTP distinto de 200 genera error controlado.
Conexión, timeout, JSON inválido y ficha con ID distinto tienen mensajes propios.
No se presenta el cuerpo de errores externos en la interfaz.
next/previous deben ser HTTPS, host exacto gutendex.com, ruta de listado,
sin credenciales ni fragmento, página positiva y misma consulta e idioma.
No se siguen enlaces de paginación a otros hosts ni se calculan offsets.
Una página fallida conserva libros y cursor; el reintento solicita ese cursor.
Los IDs repetidos se eliminan. Un next repetido detiene el avance.
No se solicitan páginas automáticamente ni mientras otra página está cargando.
Cambiar texto invalida resultados inmediatamente, antes del debounce.
Generaciones y dispose impiden aplicar respuestas o errores de consultas viejas.

10. FILTROS Y ESTADOS
Cambiar idioma cancela el debounce, reinicia resultados y paginación y consulta
con el texto actual. Los idiomas mostrados provienen de cada obra, no del filtro.
loading y loadingMore son independientes; la ficha mantiene su propio Future.
No se muestra vacío durante carga ni como reemplazo de un error.

11. FORMATOS Y ENLACES
Se reconocen application/epub+zip, text/html y text/plain, con parámetros MIME.
Solo se presentan recursos HTTPS en gutenberg.org o www.gutenberg.org, sin
credenciales, puertos alternativos, espacios, controles ni barras inversas.
Se excluyen esquemas peligrosos, hosts parecidos y formatos no compatibles.
Portadas: JPEG/PNG seguros, con respaldo de error exclusivo del módulo.
No se descargan ni interpretan libros. No hay botones de lector interno.
Como no existe una dependencia de apertura externa, las URLs se muestran
seleccionables para copiar manualmente. No se agregó url_launcher.
copyright se presenta como dato del proveedor, sin garantizar dominio público
en todas las jurisdicciones. La ficha identifica siempre Project Gutenberg.

19. CORS Y CONECTIVIDAD
No se observó ni reprodujo un error CORS: no se ejecutó el cliente en navegador.
La documentación y el código público consultados no prueban la configuración
actual del servidor ni su acceso desde el origen real de la aplicación.
En Web, un rechazo CORS impediría recibir los datos; Android no aplica el mismo
control de origen del navegador, pero sigue sujeto a TLS, red y disponibilidad.
Si ocurre: capturar URL, estado y cabeceras sin secretos; detenerse antes de
añadir proxies o modificar backend/CORS. Evaluar una instancia autorizada o
un servicio intermedio HTTPS con contrato público, host permitido y límites.
Son alternativas futuras, no implementadas ni autorizadas en este bloque.
