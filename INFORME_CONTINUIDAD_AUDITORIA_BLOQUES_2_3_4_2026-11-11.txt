5. CATÁLOGO SQL Y BLOQUE 2

LibraryController carga GET /api/me/library y GET /api/books.
El catálogo representa metadatos compartidos. La biblioteca representa pertenencia y seguimiento privados.
MainShell copia el catálogo a Home mediante catalogBooks.
Agregar exige bookId SQL confirmado.
No se convierten IDs demo a IDs SQL.
POST /api/me/library agrega; PATCH /api/me/library/{bookId} modifica; DELETE quita pertenencia.
El backend resuelve propietario desde CurrentUserService y token autenticado.
DELETE no elimina el libro del catálogo.

Si el catálogo SQL está vacío, Home autenticado no tiene libros para descubrimiento. Esto explica el vacío sin implicar eliminación de pantallas.
En Bloque 3 se debe separar descubrimiento externo y biblioteca privada.

El registro manual existente permite comenzar con catálogo vacío; cuando exista Google Books quedará como mecanismo secundario.

Riesgos previos a implementar:
