2. CAUSAS Y CORRECCIONES
WRITER: las tarjetas descartaban referencias preset: y dibujaban un placeholder distinto; creación, administración y lectura tenían resoluciones y paletas duplicadas. WriterCover centraliza classic/gold/forest/night y LiteraryCover resuelve assets/red/fallback. Se usa coverPath persistido por los modelos/repositorios existentes en creación, Mis historias, administración, editor, perfil, comunidad y lectura. Una referencia desconocida falla a una portada tipográfica de esa misma historia. No se almacena la portada únicamente en memoria ni se modifica el contrato backend.

GOOGLE BOOKS/BIBLIOTECA: existían imágenes HTTP, renderizado web dependiente de fetch/CORS y ausencia de comprobación de concordancia entre el ID del volumen y el ID de su URL. Los metadatos Google anidados podían consumirse sin comprobar su vínculo con el ID principal. Se valida la identidad en GoogleBooksClient, GoogleBooksService, BookMapper, ApiCatalogRepository y LibraryEntry. Se rechazan referencias Google con ID diferente/duplicado; se normaliza HTTPS de proveedores conocidos. No se sustituyen imágenes con una búsqueda por título, imágenes aleatorias o stock. La interfaz usa Image.network con WebHtmlElementStrategy.prefer para mostrar imágenes web mediante elemento HTML cuando corresponde; no se deshabilita seguridad de Chrome ni se crea un proxy abierto. LiteraryCover utiliza clave identidad+URL, gaplessPlayback=false y fallback propio con título/autor. Fallos se recuerdan por identidad+URL, máximo 128 entradas y dos minutos, evitando repetición en cada reconstrucción. Cambiar referencia permite un nuevo intento. No se reescriben registros antiguos: se sanea su representación de lectura.

GUTENDEX: la lectura de formats no toleraba todas las variantes MIME útiles y faltaba comprobar el ID de la ruta de portada. Se aceptan JPEG/PNG/WebP con parámetros MIME; únicamente referencias HTTPS de hosts Gutenberg admitidos y rutas correspondientes al ID de la obra. Se aprovecha formats de la respuesta, sin adivinar URLs. Sin imagen compatible se dibujan el título y autor de esa obra; no se atribuyen portadas de otras ediciones. No se modificaron los 50 libros offline ni la descarga/lectura. Consulta externa a gutendex.com/books/?ids=2000,11 devolvió HTTP 403: no se presenta como verificación positiva del API real.

RECOMENDACIONES: RecommendationService consultaba sin restricción de idioma y no existía validación final uniforme; al crecer la biblioteca entraban candidatos ingleses. Ahora solicita es y GoogleBooksClient usa langRestrict; GoogleBooksService y RecommendationService filtran idioma declarado. Flutter vuelve a filtrar en repositorio API, exploración y controlador, incluidos candidatos enriquecidos del flujo previo. Se exige es/es-* y se rechazan títulos/descripciones evidentemente ingleses mediante comprobación conservadora, sin IA nueva ni títulos inventados. Se devuelven menos obras y aviso informativo cuando faltan candidatas; no se completa con inglés. Se mantiene la generación/cancelación de respuestas del controlador y el aislamiento por cuenta; el snapshot backend se obtiene dentro del bloqueo por usuario. No se añadieron claves ni nuevas funciones Gemini. El flujo existente usa candidatos reales de Google Books y permite enriquecimiento opcional previo; no se sustituyó por contenido generado.
