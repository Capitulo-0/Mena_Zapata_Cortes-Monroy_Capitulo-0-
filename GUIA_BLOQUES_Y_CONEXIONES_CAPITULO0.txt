2. CONEXIÓN A NEON — DESARROLLO Y PRUEBAS

Neon almacena los datos persistentes; GitHub guarda el código, NO los registros.
Las ramas 'production' y 'bloque3-v4-pruebas' son independientes: cambios
posteriores en una NO aparecen automáticamente en la otra.

Para desarrollo actual, usar la rama 'bloque3-v4-pruebas'. Abrir Neon > Branches
> seleccionar la rama > Connect, y copiar la conexión DIRECTA (sin pooling).
Cada integrante debe obtener acceso autorizado y configurar en su propia sesión
PowerShell del backend (sin poner datos reales en documentos o commits):

  $env:DB_URL = 'jdbc:postgresql://HOST-DE-LA-RAMA/BASE?sslmode=require'
  $env:DB_USERNAME = 'USUARIO_AUTORIZADO'
  $secretoDb = Read-Host 'Password de Neon' -AsSecureString
  $env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $secretoDb).Password
  Remove-Variable secretoDb
  $env:SPRING_FLYWAY_ENABLED = 'false'
  $env:SPRING_JPA_HIBERNATE_DDL_AUTO = 'validate'

Los textos HOST, BASE y USUARIO son MARCADORES: reemplazarlos localmente,
no pegarlos literalmente. Confirmar que el servidor corresponde a la rama de
pruebas antes de arrancar Spring Boot. No ejecutar migraciones sobre production.
Flyway desactivado y Hibernate validate protegen el esquema de cambios automáticos,
pero NO impiden todas las escrituras de la aplicación.

3. FIREBASE Y GOOGLE BOOKS — CONFIGURACIÓN LOCAL

Firebase Authentication: cada integrante debe estar autorizado en el proyecto
Firebase correspondiente. Compartir una cuenta de Gmail NO configura
por sí solo las credenciales, las sesiones o los permisos en cada computador.
Cada cuenta Firebase tiene identidad propia; los libros privados se asocian a
esa identidad, no al computador.

Backend (en la misma sesión PowerShell donde se configura Neon):

  $env:FIREBASE_PROJECT_ID = 'ID_DEL_PROYECTO_FIREBASE'
  $env:GOOGLE_APPLICATION_CREDENTIALS = 'RUTA_LOCAL_AL_JSON_FIREBASE_ADMIN'
  $env:APP_CORS_ALLOWED_ORIGINS = 'http://localhost:7357'
  # Configurar también GOOGLE_BOOKS_API_KEY con su valor autorizado,
  # sin escribirlo en Git ni compartirlo por chat.

GOOGLE_APPLICATION_CREDENTIALS debe apuntar a un archivo real de cuenta de
servicio, guardado FUERA del repositorio, con permisos restringidos. No copiar
archivos privados de un compañero al repo ni publicar esa clave.

Flutter Web usa su configuración local válida en:
  android/config/firebase_web.local.json
No mezclar comandos PowerShell con el JSON. Cada integrante necesita preparar
su configuración Web para el mismo proyecto Firebase autorizado.

4. EJECUCIÓN LOCAL

Terminal A: dentro de backend/, con TODAS las variables del backend definidas
en esa MISMA terminal:
  mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=8086"
Dejarla abierta cuando aparezca 'Started BackendApplication'.

Terminal B: dentro de android/:
  flutter run -d chrome --web-hostname localhost --web-port 7357 --dart-define=API_BASE_URL=http://localhost:8086 --dart-define-from-file=config/firebase_web.local.json

Las variables $env: no se comparten automáticamente entre terminales y no
persisten al cerrar la sesión. Cambiar de carpeta con cd tampoco las transfiere.
Para un despliegue público se configurarán secretos en el hosting del backend;
los evaluadores NO tendrán que ejecutar PowerShell.
