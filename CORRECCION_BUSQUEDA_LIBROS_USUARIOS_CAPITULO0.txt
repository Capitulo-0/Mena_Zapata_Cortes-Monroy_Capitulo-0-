2. CAUSA ORIGINAL

home_search_section.dart buscaba usuarios antes que libros.
_searchUsersFirst solo iniciaba Google Books cuando usuarios devolvía una lista vacía. Una coincidencia de usuario o un fallo de ese servicio impedía consultar libros.
_buildUniversalResults elegía una sola categoría; las cargas y errores de usuarios también reemplazaban el contenido literario.
Las sugerencias repetían el mismo patrón excluyente en _loadPreview y _buildSearchPreview.
El botón Más resultados y _loadMoreBooks dependían del estado de usuarios.
El renderizado de libros ocultaba resultados previamente cargados si había error de paginación.
CatalogController captura los fallos y los guarda en .error; no basta con capturar excepciones en el widget.

4. SOLUCIÓN EXACTA

Búsqueda general:
- _search inicia libros y usuarios de forma independiente, sin esperar que termine uno para iniciar el otro.
- Se reemplaza _searchUsersFirst por una consulta de usuarios que solo administra sus propios datos, carga y error.
- _buildUniversalResults compone la sección de libros y la de usuarios; no selecciona una para ocultar la otra.
- Se conserva el botón Volver de libros y se retira el duplicado de la sección de usuarios.
- Se conservan filas de usuario, tarjetas literarias, estilos existentes y callbacks de navegación.

Filtros:

- Texto libre general consulta ambos servicios.
- Título, autor, ISBN, género y orden literario mantienen búsqueda exclusivamente de libros.
- No se modificaron la construcción de consultas, el filtrado local ni el ordenamiento.

Errores y reintentos:
- Usuarios tiene su indicador, error y reintento propio.
- Libros interpreta también CatalogController.error.
- Reintentar usuarios no consulta ni limpia libros.
- Reintentar libros no consulta ni limpia usuarios.
- No se muestran contadores vacíos durante carga ni después de un error como si fuera una respuesta válida.
- Los errores se presentan dentro de la sección correspondiente.

Sugerencias:
- Se mantiene el temporizador de 400 ms.
- Al vencer el debounce se inicia la consulta de libros y, en búsqueda general, la de usuarios de forma independiente.
- Se conserva una tarjeta de sugerencia literaria y se permite mostrar al mismo tiempo las filas de usuarios.
- La carga y el error de sugerencias de usuarios se separan del catálogo de sugerencias.
- Los reintentos consultan solo el servicio fallido.
- El texto de vacío de sugerencias literarias menciona libros para no comunicar un vacío global mientras usuarios tiene resultados.

Paginación:
- Más resultados y _loadMoreBooks ya no dependen de carga, error o coincidencias de usuarios.
- Se conserva CatalogController.more(), su cursor y deduplicación por Google Volume ID.
- Si una página adicional falla, las tarjetas ya cargadas permanecen visibles.
- El reintento usa more() mientras exista cursor; si falló la consulta inicial, repite esa búsqueda de libros.
- No se mezcla el catálogo de sugerencias con el cursor de resultados.

Respuestas obsoletas:
