6. PREPARACION PARA NEON
V1-V3 sin diferencias frente a develop. V4 es aditiva:
ALTER TABLE books ADD COLUMN google_volume_id VARCHAR(128);
ALTER TABLE books ADD COLUMN external_metadata TEXT;
ALTER TABLE books ADD CONSTRAINT uq_books_google_volume UNIQUE (google_volume_id);

Solo modifica books. Ambas columnas permiten NULL y no tienen valor por defecto.
No contiene DROP, DELETE, UPDATE, cambios de claves existentes ni cambios a
users o library_entries.
Desde V3, registros previos quedan con columnas nuevas en NULL. PostgreSQL permite
varios NULL bajo esta restriccion; rechaza identificadores no nulos repetidos.
La prueba H2 existente verifica preservacion de un libro y avance 73/300,
unicidad externa y segunda ejecucion Flyway sin nueva migracion; no se ejecuto ahora.

Riesgos operativos:
- ALTER TABLE y creacion de unicidad pueden bloquear operaciones.
- Conflicto si columnas/restriccion ya existen fuera de Flyway.
- Divergencias de historial/checksums Flyway con migraciones locales.
- Arranque accidental del backend: spring.flyway.enabled=true.
- Respaldo insuficiente para recuperar datos si falla una operacion posterior.
Hibernate usa ddl-auto=validate; no sustituye el control de migraciones.
No se inspecciono la base destino y no se certifica su estado.
